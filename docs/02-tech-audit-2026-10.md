## 1. Критические ошибки: страницы в sitemap.xml отдают не 200

Проверено трижды подряд — ошибки стабильные, не разовые.

| Код | URL | Комментарий |
|---|---|---|
| **500** | `/news/` | Раздел статей целиком. Статьи `/news/*` при этом открываются |
| **500** | `/bukhgalterskie-uslugi/bukhgalterskoe-soprovozhdenie/` | Коммерческая страница услуги |
| **500** | `/bukhgalterskie-uslugi/prochie-uslugi/` | Коммерческая страница услуги |
| **403** | `/deklaratsii-3-ndfl/vernut-nalogi-v-ofise/neobkhodimye-dokumenty/` | |
| **403** | `/yuristy-dlya-biznesa/dlya-malogo-biznesa-do-50-mln-rub-vyruchki-v-god/` | |
| **404** | `/policy/novyy-razdel/` | Технический мусор, удалить из ИБ |

**Почему критично:** 500 — это не «страница не найдена», для поисковика это «сайт сломан».
Яндекс и Google снижают частоту обхода всего сайта, если регулярно получают 5xx.
Страницы заявлены в sitemap.xml, то есть робота на них отправляют принудительно.

**Что делать:** разобрать причину 500 в логах (`/bitrix/php_interface/`, вероятно
обращение к несуществующему инфоблоку или свойству), починить или отдать 410/301.
Из sitemap убрать всё, что не 200.

## 2. Дубли страниц

Одинаковый контент и **одинаковый H1** на разных URL:

| Пара | H1 | Слов |
|---|---|---|
| `/bukhgalterskie-uslugi/dlya-krupnogo-biznesa-/`<br>`/bukhgalterskie-uslugi/dlya-krupnogo-biznesa-svyshe-800-mln-rub-vyruchki-v-god/` | «Бухгалтерские услуги для крупного бизнеса» | 156 / 176 |
| `/bukhgalterskie-uslugi/dlya-srednego-biznesa-/`<br>`/bukhgalterskie-uslugi/dlya-srednego-biznesa-do-800-mln-rub-vyruchki-v-god/` | «Бухгалтерские услуги для среднего бизнеса» | 134 / 176 |
| `/bukhgalterskie-uslugi/dlya-srednego-biznesa-do-800.../dlya-krupnogo-biznesa-svyshe-800.../` | то же | 138 |
| `/cookies/` и `/fayly-kuki/` | — | — |

Вложенный URL «средний бизнес → крупный бизнес» — ошибка структуры ИБ.

Меню и страница листинга ведут на **разные** URL из пары: меню → `dlya-krupnogo-biznesa-`,
листинг `/bukhgalterskie-uslugi/` → `dlya-krupnogo-biznesa-svyshe-800...`. Вес размазан
между дублями, поисковик сам выбирает «главную» версию.

**Что делать:** оставить по одному URL (короткий — чище), остальные 301 на него,
поправить ссылки в меню, листинге и подвале.

## 3. `rel="canonical"` отсутствует на всех 105 рабочих страницах

Ни одна страница не имеет `<link rel="canonical">`. При этом на сайте есть:
дубли из п. 2, пагинация `?PAGEN_1=`, UTM-метки (закрыты только в robots.txt,
а это не директива для Google).

**Что делать:** вывести canonical в `header.php` шаблона `main2025` —
по умолчанию текущий URL без GET-параметров, с возможностью переопределить
через свойство страницы.

## 4. Заголовочная структура: H2/H3 на сайте фактически нет

Из 37 страниц услуг **у 33 ноль или один H2**, и этот единственный H2 — заголовок
формы обратного звонка «Не знаете какую услугу выбрать?», то есть он не про услугу.

Все смысловые заголовки свёрстаны дивами: `.cases__title`, `.advantages-working__title`,
`.more-services__title`, `.company-numbers__title`, `.black-service-single-hero__title`.

На главной странице: **H1 — один, H2 — ноль, H3 — ноль.**

**Что делать:** заменить теги на `h2`/`h3` в шаблоне (классы и стили оставить,
меняется только имя тега — визуально ничего не поедет). Это работа на пару часов,
а эффект ощутимый: сейчас поисковик не видит структуры документа.

## 6. Внутренняя перелинковка

Ссылки на страницы услуг идут почти только из сквозного мега-меню. Сквозная ссылка
есть на каждой странице сайта и передаёт мало веса — поисковик различает
навигационные и контентные ссылки.

Контентных ссылок (внутри `<main>`) на страницы услуг — 0–1 на большинство URL:

```
0 ссылок: /yuristy-dlya-biznesa/yuridicheskoe-obsluzhivanie/
0 ссылок: /yuristy-dlya-biznesa/predstavitelstvo-v-sudakh/
0 ссылок: /yuristy-dlya-biznesa/zashchita-intellektualnykh-prav/
0 ссылок: /deklaratsii-3-ndfl/ и все 3 дочерние
0 ссылок: /bukhgalterskie-uslugi/dlya-krupnogo-biznesa-/
```

Листинг `/bukhgalterskie-uslugi/` показывает **только 3 ссылки** (малый/средний/крупный
бизнес), хотя в разделе 11 страниц. Абонентское обслуживание, восстановление учёта,
консультации, заполнение деклараций в листинге не представлены вообще.

→ Это и есть задача №1 «Другие услуги». См. `specs/`.

Детальные страницы кейсов поисковику не заявлены.

## 8. Редирект уводит с HTTPS на HTTP

```
GET https://1-plus-1.ru/yuristy-dlya-biznesa/yuridicheskoe-obsluzhivanie
→ 301 http://1-plus-1.ru/yuristy-dlya-biznesa/yuridicheskoe-obsluzhivanie/
```

Редирект «дослешивания» отдаёт `http://`, а не `https://`. Получается лишний хоп
`https → http → https`. Плюс в листинге `/yuristy-dlya-biznesa/` часть ссылок стоит
без слеша — то есть сайт сам гоняет робота по этой цепочке.

**Что делать:** в правиле редиректа брать схему из запроса. Заголовка HSTS тоже нет.

## 10. Прочее

- `cache-control: no-store, no-cache, must-revalidate` на главной — браузерное
  и CDN-кэширование отключено полностью. Напрямую бьёт по скорости (п. 1 аудита подрядчиков).
- В ряде `<title>` не раскодированы HTML-сущности: `&mdash;`, `&quot;` попадают
  в выдачу как есть — баг шаблона тайтла.
- 44 тайтла длиннее 70 символов — обрезаются в сниппете. Хвост `— Компания "1+1"`
  съедает 18 символов на каждой странице.
- Блок «Отраслевая экспертиза» на главной — одна SVG-картинка, ноль индексируемого текста.
- `meta keywords` заполнен устаревшим списком (ЕНВД отменён с 2021). На ранжирование
  не влияет, но выглядит как заброшенный сайт.
- Расхождения в цифрах между страницами: главная «15 лет на рынке» и «37-е место RAEX»,
  `/about/` «основана в 2011» + «ТОП-50 RAEX», title `/about/` «12 лет лидерства»,
  презентация «39 место». Нужно свести к одной версии.
