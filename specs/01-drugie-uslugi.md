# ТЗ: блок «Другие услуги» на страницах услуг

Версия 1 · 27.10.2026 · 1-plus-1.ru · 1С-Битрикс, шаблон `/local/templates/main2025/`

Визуальная версия с превью: см. артефакт «ТЗ: блок "Другие услуги"».

---

## 1. Зачем

Ссылки на страницы услуг идут почти только из сквозного мега-меню. Сквозная ссылка
стоит на каждой странице сайта и передаёт мало веса — поисковик отличает
навигационные ссылки от контентных.

Контентных ссылок (внутри `<main>`) на большинство страниц услуг — **ноль**:

```
0 — /yuristy-dlya-biznesa/yuridicheskoe-obsluzhivanie/
0 — /yuristy-dlya-biznesa/predstavitelstvo-v-sudakh/
0 — /yuristy-dlya-biznesa/zashchita-intellektualnykh-prav/
0 — /yuristy-dlya-biznesa/soprovozhdenie-vneshneekonomicheskoy-deyatelnosti/
0 — /bukhgalterskie-uslugi/dlya-krupnogo-biznesa-/
0 — /deklaratsii-3-ndfl/ и все три дочерние
```

Блок решает три задачи: распределяет вес между страницами услуг, связывает разделы
между собой и ловит посетителя, попавшего не на ту страницу.

---

## 2. Что размещаем

Секция из четырёх карточек-ссылок. Заголовок — **«Другие услуги»**. Карточка —
название услуги и стрелка, кликабельна целиком.

**Верстать с нуля не нужно.** На сайте есть готовый блок с нужным видом —
«Ещё услуги» на главной, класс `.more-services`. Берём вёрстку и стили как есть,
меняем заголовок и источник данных.

Карточки **без изображений** — сознательный выбор: не нужно заводить картинку
на каждую из 29 услуг, и блок не добавляет веса странице (PageSpeed на мобильных
сейчас 29–51 из 100).

---

## 3. Место на странице

**Правило вставки:** блок ставится непосредственно перед секцией `manager-callback` —
это форма обратного звонка и подвал. Правило одно для всех 29 страниц, исключений нет.

> **Важно.** В шаблоне есть секция `service-choose-callback` («Не знаете какую услугу
> выбрать?»), но она **закомментирована в HTML** — в браузере её нет ни на одной
> из 29 страниц услуг. Проверено обходом всех страниц. Ориентироваться нужно
> на `manager-callback`. Если секцию когда-нибудь раскомментируют, блок «Другие услуги»
> должен остаться выше неё.

Пример — «Бухгалтерское сопровождение»:

```
black-service-single-hero
advantages-working
tariffs
how-work
company-numbers-2
your-state
reviews
partners
→ more-services more-services--related   ← БЛОК СЮДА
service-choose-callback   (закомментирована, в браузере её нет)
manager-callback
```

Пример — «Восстановление учёта»:

```
black-service-single-hero
advantages-working
responsibility-insured
→ more-services more-services--related   ← БЛОК СЮДА
service-choose-callback   (закомментирована, в браузере её нет)
manager-callback
```

**Почему здесь.** Человек дочитал страницу, предложение он уже видел. Дальше
либо заявка, либо соседняя услуга. Блок не перехватывает внимание до оффера
и не отодвигает форму так далеко, чтобы её перестали видеть.

## 4. Внешний вид

Блок не переиспользует вёрстку с главной: карточка другая — в ней появилась
подпись под названием, и убрана фиксированная высота 300px.

| Параметр | Значение |
|---|---|
| Заголовок блока | «Другие услуги», тег `<h2>`, 40px / 600 / 1.1 |
| Карточек | 4 |
| Фон секции | `#f2f3ed` |
| Сетка | 4 колонки · ≤1199px — 2 колонки · ≤767px — 1 колонка |
| Отступ между карточками | 20px |
| Фон карточки | `#ffffff` |
| Скругление | 20px |
| Внутренний отступ | 28px сверху/снизу, 26px по бокам |
| Высота карточки | По содержимому, одинаковая внутри ряда |
| Стрелка | 22×22, справа сверху |
| Название услуги | 20px / 600 / 1.28, прижато к низу карточки |
| Подпись под названием | 15px / 400 / 1.4, цвет `#6b6a5f` |
| Ховер | Цвет `#d73a61`, переход `.3s` |
| Фокус с клавиатуры | Видимая обводка — **надо добавить**, сейчас её нет |
| Цена в карточке | **Не показываем** |

**Сетка задаётся явными брейкпоинтами, не `auto-fit`.** С `auto-fit` на 1024px
ряд ломается на три колонки, и четвёртая карточка остаётся одна во втором ряду.

**Высота карточек внутри ряда должна совпадать.** `<li>` в гриде растягивается
сам, а карточка внутри — нет, поэтому у `<li>` нужен `display:flex`, а у карточки
`width:100%; height:100%`. Без этого четвёртая карточка ниже остальных.

### Два типа блока

Выделение карточек не настраивается вручную на каждой странице. Тип блока
определяется одним условием: есть ли среди четырёх карточек «Бухгалтерское
сопровождение».

| | Тип 1 | Тип 2 |
|---|---|---|
| Условие | В блоке есть бухсопровождение | Его нет |
| Страниц | 20 | 9 |
| Что выделено | Первая карточка | До двух приоритетных |
| Фон выделенной | `#d73a61` | `#e6e7cf` |
| Текст на выделенной | `#ffffff`, подпись `rgba(255,255,255,.88)` | `#1b1b1b`, подпись `#5f6047` |

На страницах типа 1 «Бухгалтерское сопровождение» всегда стоит **первой**
карточкой — это зафиксировано в карте перелинковки, подрядчику ничего
вычислять не нужно. Конкретное выделение по каждой странице — в колонке
«Выделение» файла `perelinkovka-drugie-uslugi.xlsx`.

**Состояния:**

- Обычное: текст и стрелка наследуют цвет карточки.
- Наведение: `#d73a61`, переход `.3s`.
- Фокус с клавиатуры: видимая обводка. **Надо добавить** — сейчас её нет.
- Кликабельна вся карточка, а не только название.

**Если связей меньше двух — блок не выводится вообще.** Пустая секция хуже,
чем её отсутствие.

## 6. Как собрать в Битриксе

### Шаг 1. Свойство инфоблока

| Параметр | Значение |
|---|---|
| Название | Другие услуги |
| Символьный код | `OTHER_SERVICES` |
| Тип | Привязка к элементам |
| Множественное | Да |
| Количество значений | 4 |
| Вид списка | Выпадающий список с поиском |

Второе свойство — для подписей:

| Параметр | Значение |
|---|---|
| Название | Подписи к другим услугам |
| Символьный код | `OTHER_SERVICES_TEXT` |
| Тип | Строка |
| Множественное | Да |
| Количество значений | 4 |

Значения сопоставляются по порядку: первая подпись относится к первой
связи, вторая ко второй и так далее. Подпись зависит от пары «откуда → куда»,
поэтому хранить её на самой услуге нельзя: «Юридическое обслуживание»
со страницы договоров и со страницы трудовых споров подписано по-разному.

### Шаг 1а. Выделение карточек — считается, не настраивается

Отдельного свойства «выделить карточку» не нужно. Шаблон определяет тип
блока сам:

```php
$ACCENT_ID = 000;                 // ID элемента «Бухгалтерское сопровождение»
$PRIORITY  = [000, 000, 000, 000, 000];  // ID: управленческий учёт, инициативный аудит,
                                         // оптимизация налогообложения, судебная экспертиза,
                                         // затем юридическое обслуживание — в этом порядке

$ids = array_column($arResult['ITEMS'], 'ID');

if (in_array($ACCENT_ID, $ids)) {
    // тип 1: акцентной становится первая карточка, она же бухсопровождение
    $mark = [0 => 'accent'];
} else {
    // тип 2: до двух карточек из списка приоритета, в порядке приоритета
    $mark = [];
    foreach ($PRIORITY as $pid) {
        $pos = array_search($pid, $ids, true);
        if ($pos !== false) { $mark[$pos] = 'green'; }
        if (count($mark) === 2) { break; }
    }
}
```

Класс карточки: `rs-card--accent` для `accent`, `rs-card--green` для `green`,
без модификатора для остальных.

> Порядок связей задаёт контент-менеджер, и на 20 страницах типа 1
> «Бухгалтерское сопровождение» стоит первым по карте из раздела 7.
> Если его случайно переставят, акцент уедет на чужую карточку —
> это проверяется в чеклисте приёмки.

> **Привязка должна работать между инфоблоками.** Со страницы бухуслуги нужно
> уметь сослаться на юридическую услугу и наоборот. Если услуги разных разделов
> лежат в разных инфоблоках — настроить привязку так, чтобы в списке были доступны
> элементы всех инфоблоков услуг. Иначе половина карты из раздела 7 не соберётся.

### Шаг 2. Шаблон компонента

Создать шаблон `related_services` для `bitrix:news.list` в
`/local/templates/main2025/components/bitrix/news.list/`. Вёрстка — из раздела 5.

### Шаг 3. Вызов в шаблоне детальной страницы

```php
<?php
$arOther = $arResult['PROPERTIES']['OTHER_SERVICES']['VALUE'] ?? [];
// меньше двух связей — блок не выводим
if (count($arOther) >= 2):
    $APPLICATION->IncludeComponent(
        "bitrix:news.list",
        "related_services",
        [
            "IBLOCK_TYPE"           => "services",
            "IBLOCK_ID"             => "",                  // пусто = искать по всем ИБ типа
            "NEWS_COUNT"            => 4,
            "FILTER_NAME"           => "arRelatedFilter",   // ["ID" => $arOther]
            "SORT_BY1"              => "SORT",
            "SORT_ORDER1"           => "ASC",
            "FIELD_CODE"            => ["ID", "NAME", "DETAIL_PAGE_URL"],
            "PROPERTY_CODE"         => [],                  // подписи передаются через $arParams
            "CACHE_TYPE"            => "A",
            "CACHE_TIME"            => "36000000",
            "CACHE_GROUPS"          => "N",
            "SET_LAST_MODIFIED"     => "N",
            "SET_TITLE"             => "N",
            "ADD_SECTIONS_CHAIN"    => "N",
            "DISPLAY_DATE"          => "N",
            "DISPLAY_PICTURE"       => "N",
            "DISPLAY_PREVIEW_TEXT"  => "N",
        ]
    );
endif;
?>
```

> **Порядок карточек** должен совпадать с порядком связей в свойстве, а не
> с сортировкой элементов. Если штатно не держится — отсортировать результат
> в шаблоне по массиву `$arOther`.

### Шаг 4. Кэширование

Управляемый кэш (`CACHE_TYPE = "A"`, `CACHE_TIME = 36000000`) со сбросом по
изменению инфоблока. Блок не должен добавлять запросов к базе на каждый хит.

### Шаг 5. Заполнение

Контент-менеджер проставляет связи и подписи по карте из раздела 7
и по файлу `perelinkovka-drugie-uslugi.xlsx`: 29 страниц × 4 связи × 4 подписи.
Дальше правки делаются из админки, без подрядчика.

## 7. Карта перелинковки

29 страниц, по 4 ссылки, 116 ссылок всего. **Жирным** — ссылки в другой раздел
сайта, таких 64 из 116.

> **Подбор ручной, и это принципиально.** Автоподбор «случайные услуги из того же
> раздела» даст мусор: на «Восстановлении учёта» покажется «Бухгалтерия для малого
> бизнеса», а это не соседняя услуга, а родительская категория.
>
> Правило карты: три ссылки на смежные по смыслу услуги плюс минимум одна
> в другой раздел. Карта проверена: страниц без входящих ссылок нет,
> страниц без кросс-ссылки нет.

> **Финансовый консалтинг в блоке — это допродажа, а не иерархия.** Со страниц
> бухгалтерских услуг блок ведёт в том числе на финансовый консалтинг, таких ссылок 11.
> Сделано намеренно: консалтинг второй в приоритете продаж, бухгалтерский раздел —
> самый посещаемый. Это **не отменяет задачу 4**: из мега-меню в ветке «Бухгалтерские
> услуги» пункты «Инициативный аудит» и «Финансовый / Налоговый консалтинг» убираются,
> там они создают ложную иерархию и вешают два анкора на один адрес.


### Логика подбора: воронка в главные услуги

Человек пришёл на страницу не просто так. Его ситуация говорит о проблеме,
а следующая услуга эту проблему закрывает. Пример: **восстановление учёта — это улика,
что прежний бухгалтер не справился**, значит клиенту нужен не только ремонт прошлого,
но и новый бухгалтер на будущее.

Приоритеты: ① абонентское бухобслуживание, ② финансовый и налоговый консалтинг,
③ юридическое обслуживание. На приоритетные страницы ведут **66 ссылок из 116** — 20, 26 и 20.

#### Что приводит клиента в абонентское обслуживание

| Страница клиента | Сила входа | Что говорит ситуация клиента | Ссылка |
|---|---|---|---|
| **Восстановление учёта** | сильный | Учёт разваливали месяцами, а то и годами. Это прямая улика: прежний бухгалтер не справился. Клиенту нужен не только ремонт прошлого, но и новый бухгалтер на будущее | поз. 1 |
| **Защита от налоговой** | сильный | Проверка пришла и нашла нарушения. Это доказательство, что учёт вели плохо, полученное от самой налоговой | поз. 1 |
| **Инициативный аудит бухгалтерии** | сильный | Аудит заказывают, когда своей бухгалтерии уже не доверяют. Аудит находит ошибки и подтверждает подозрение — бухгалтера пора менять | поз. 1 |
| **Консультация бухгалтера** | сильный | Задаёт вопросы чужим бухгалтерам. Значит, своему или не доверяет, или его нет | поз. 1 |
| **Подбор главбухов** | сильный | Клиент уже признал, что бухгалтерия не закрыта, и ищет человека в штат. Мы предлагаем не нанимать одного, а получить команду дешевле | поз. 1 |
| **Регистрация и ликвидация бизнеса** | сильный | Компании ноль дней, бухгалтера нет вообще. Решение принимается прямо сейчас, и второй раз этот момент не повторится | поз. 1 |
| **Внесение изменений в ЕГРЮЛ и ЕГРИП** | средний | Меняют директора или участника. Это типичный момент, когда меняют и бухгалтера | поз. 4 |
| **Воинский учёт** | средний | Новая обязанность со штрафами, которую ведут кадры и бухгалтерия. Если их нет, нужны обе функции | поз. 1 |
| **Заполнение деклараций** | средний | Сдаёт отчётность разово. Значит, постоянного бухгалтера нет либо ему не доверяют отчётность | поз. 1 |
| **Оптимизация налогообложения** | средний | Платит больше, чем мог бы. Значит, бухгалтер только считает, а планированием не занимается | поз. 1 |
| **Правовой аудит** | средний | Проверяют риски в документах. Учётные риски вскрываются там же | поз. 2 |

## 8. Чего делать нельзя

- **Никаких `javascript:void(0)` и JS-навигации.** Только обычные
  `<a href="/путь/">`. Ссылка, которую не видит поисковик, не передаёт вес —
  тогда вся задача теряет смысл.
- **Адреса строго со слешем на конце.** Сейчас в листинге `/yuristy-dlya-biznesa/`
  часть ссылок без слеша, и сайт гоняет робота через редирект. Хуже того,
  редирект уводит на `http://` вместо `https://` — лишний хоп на каждой такой ссылке.
- **Никаких `rel="nofollow"`** на этих ссылках.
- **Анкор — название услуги** из таблицы раздела 7. Не «подробнее», не «читать далее».
- **Заголовок блока — `<h2>`**, не `<div>`. Класс `more-services__title` оставить.
- **Не выводить блок на листингах разделов** (`/bukhgalterskie-uslugi/`,
  `/finansoviy-konsalting/`, `/yuristy-dlya-biznesa/`, `/deklaratsii-3-ndfl/`) —
  они и так состоят из ссылок на дочерние страницы.
- **Не ставить ссылку на саму себя** — отфильтровать в шаблоне.
