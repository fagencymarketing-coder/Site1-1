# Задача 2. Кейсы и статьи на главной странице

---

## Что уже есть

**Кейсы на главной уже стоят** — секция `.cases`, три карточки, кнопка «Смотреть все
кейсы». Блок рабочий, переделывать его не нужно.

**Статей на главной нет вообще.** Это и есть задача.

Хорошая новость: блок статей **не нужно верстать с нуля**. Страница `/blog/`
использует ту же вёрстку, что и кейсы, с одним модификатором:

```html
<section class="cases cases--blog">
```

Внутри — тот же `.case-card`, только в `.case-card__number` вместо «Кейс № 1»
выводится дата: `10.10.2026`. Для подрядчика это копия существующей секции
с другим инфоблоком в компоненте.

## Куда ставить блок статей

### Вариант А — после «Отзывов», перед «Партнёрами» (позиция 11.5) ⭐ рекомендую

```
… reviews (отзывы) → [СТАТЬИ] → partners → team → certificates+FAQ
```

**Почему так.** Верх главной — коммерческий: кто мы, сколько стоит, чем
застрахованы, какие результаты. Статьи — информационный контент, он не должен
стоять между оффером и доказательствами. Но и в самый низ его прятать нельзя:
блок в подвале почти не кликают и вес он передаёт слабо.

Позиция после отзывов — точка, где читатель уже прогрелся. Кто готов — оставляет
заявку в форме ниже, кто ещё изучает — уходит в блог и остаётся на сайте.

Плюс кейсы (поз. 7) и статьи (поз. 11.5) разнесены четырьмя секциями. Два
одинаковых по вёрстке блока подряд выглядели бы как ошибка.

### Вариант Б — сразу после «Кейсов» (позиция 7.5)

```
… cases → [СТАТЬИ] → industry-examination → more-services …
```

Выше по странице = больше внутреннего веса на статьи и выше кликабельность.
Минус: два визуально одинаковых блока карточек подряд. Лечится тем, что у статей
другой фон секции (светлый вместо белого) и другой заголовок.

Этот вариант стоит брать, **если приоритет — быстро разогнать блог**.

### Вариант В — объединить кейсы и статьи в один блок с табами

Не советую. Контент во второй вкладке поисковик видит хуже, появляется JS там,
где можно обойтись без него, а скорость загрузки у нас уже проблемная.

## Как должен выглядеть блок

```
┌─────────────────────────────────────────────────────────────┐
│  Блог и аналитика                      [Смотреть все статьи] │
│                                                              │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐                 │
│  │  фото    │   │  фото    │   │  фото    │                 │
│  ├──────────┤   ├──────────┤   ├──────────┤                 │
│  │10.10.2026│↗  │02.10.2026│↗  │25.09.2026│↗                │
│  │Ошибки    │   │Ликвидация│   │Амнистия  │                 │
│  │бухгалтера│   │компании  │   │за дробле…│                 │
│  └──────────┘   └──────────┘   └──────────┘                 │
│                                                              │
│                    [Смотреть все статьи]  ← мобильная версия │
└─────────────────────────────────────────────────────────────┘
```

Один в один как блок кейсов. Отличия:

| Элемент | Кейсы | Статьи |
|---|---|---|
| Заголовок | «Кейсы» | **«Блог и аналитика»** |
| Кнопка | «Смотреть все кейсы» → `/cases/` | **«Смотреть все статьи» → `/blog/`** |
| Метка в карточке | «Кейс № 1» | **дата публикации** |
| Карточек | 3 | 3 |

**Почему «Блог и аналитика», а не просто «Блог».** Слово «блог» обещает заметки
«о нас», а у вас в разделе разборы амнистии за дробление, ЕНС, ошибок в учёте —
это экспертиза. Заголовок должен это отражать, иначе блок не кликают.

---

## Какие статьи выводить

**Не последние по дате.** Автовывод свежих даст на главной случайный материал.

Выводим **закреплённые вручную 3 статьи** — свойство инфоблока `SHOW_ON_MAIN`
(тип «Да/Нет») + сортировка. Контент-менеджер отмечает галочкой, что показывать.

Стартовый набор — три самые сильные:

1. `/news/samye-rasprostranennye-kosyaki-v-bukhgalterii-kotorye-my-vyyavlyaem-pri-auditakh-i-chem-oni-grozyat/`
   «Ошибки бухгалтера: восемь примеров из практики аудита» — прямо продаёт
   инициативный аудит и восстановление учёта
2. `/news/amnistiya-za-droblenie-biznesa-kak-ona-rabotaet-i-chto-uspet-do-kontsa-2026-goda/`
   «Амнистия за дробление бизнеса» — горячая тема с дедлайном, ведёт в оптимизацию налогообложения
3. `/news/likvidatsiya-kompanii-kak-zavershit-biznes-bez-lishnikh-riskov/`
   «Ликвидация компании без лишних рисков» — ведёт к юристам

Каждая закрывает свой раздел услуг. Это не случайность — блок статей на главной
должен работать как витрина трёх направлений.

## Техническая часть

Компонент: `bitrix:news.list`, шаблон — копия шаблона блока кейсов.

```php
$APPLICATION->IncludeComponent("bitrix:news.list", "main_blog", [
    "IBLOCK_ID"        => <ID инфоблока блога>,
    "NEWS_COUNT"       => 3,
    "SORT_BY1"         => "SORT",
    "SORT_ORDER1"      => "ASC",
    "SORT_BY2"         => "ACTIVE_FROM",
    "SORT_ORDER2"      => "DESC",
    "FILTER_NAME"      => "arMainBlogFilter",   // PROPERTY_SHOW_ON_MAIN = Y
    "FIELD_CODE"       => ["ID", "NAME", "ACTIVE_FROM", "PREVIEW_PICTURE", "DETAIL_PAGE_URL"],
    "CACHE_TIME"       => "36000000",
    "CACHE_TYPE"       => "A",
    "SET_LAST_MODIFIED" => "N",
]);
```

Требования к вёрстке:

- Заголовок блока — **`<h2>`**, не `<div class="cases__title">`.
  Сейчас на главной ноль H2 — это отдельная проблема, но новый блок
  хотя бы не должен её усугублять.
- Картинки — `loading="lazy"`, `width`/`height` проставлены (как в блоке кейсов),
  формат webp через `cssinliner_webp`.
- Ссылка — весь заголовок карточки, обычный `<a href>`.

## Заодно по кейсам (дешёвые правки в том же заходе)

1. **Детальные страницы кейсов не заявлены в `sitemap.xml`.** В карте сайта есть
   только раздел `/cases/`, а семь страниц кейсов — нет. Добавить в sitemap.
2. **Опубликовано 7 кейсов из 15.** В файле «Все кейсы.xlsx» лежат ещё восемь
   готовых: экспорт с НДС 0%, стоматология с налогом 0%, убыток 20 млн в IT,
   возврат 850 000 ₽ в НКО, экономия 3 млн в развлечениях и другие. Это готовый
   контент под отраслевые запросы, он просто не используется.
3. **Кейсы лежат на `.html`**, всё остальное на сайте — со слешем.
   Менять URL уже опубликованных не стоит (потеряем историю), но новые
   лучше заводить в единой схеме `/cases/<code>/`.
